Two new words

Problem
A value that one of the seven mappings can't use as it is: HOLD as a side, N/A as a quantity, a link to a row that doesn't exist.
Outcome
What then happens to the trade. There are exactly five, from mildest to strongest.

The five outcomes

Every problem, by kind of mapping

Each problem belongs to one of the seven kinds from step 3: it is the moment that mapping can't do its job. Kinds 6 Calculate and 7 Nest have no problems of their own, because they only run on trades that passed every check.

Two things look like problems but aren't. A link can point to a row later in the file, and order doesn't matter. An instrument's issuer or underlying that can't be found simply leaves that part empty; only the trade's own links can reject it.

What if our trade had one bad value?

Our trade only had problems that end as Fixed or Filled. Here is what one change to its row would do.

side = HOLD

1Clean can't make it BUY or SELL, so it becomes empty. Rejected, and the line in rejects.ndjson is:

{"trade_id": "TR0000000042", "errors": ["E_SIDE_INVALID"], "warnings": ["W_SETTLEMENT_IMPUTED"], "record": {…, "side": null, …}}

The record holds the cleaned values, so you can see which one failed.

counterparty_id = CP9999999

4Look up finds no such company. Rejected with E_COUNTERPARTY_UNRESOLVED; there would be nothing to copy into counterparty.

Aurora Bank's parent = CP9999999

5Walk stops at Aurora Bank. Flagged: the trade is still delivered with W_COUNTERPARTY_PARENT_UNRESOLVED, Aurora Bank becomes its own top company (depth 0), and the exposure is counted under Aurora Bank instead of Summit Group.

the same row twice

The second copy has a trade id already seen. Dropped before any check. The first copy goes on as normal, and the trade tracker shows the second as a duplicate of the first.

Some rejections can be switched off

On the dashboard's Rules tab, five of the thirteen reasons can be switched off for later runs. A trade whose only problems are switched off is then delivered. The other eight are locked, and the reason is always the same: a later mapping needs that value.

Locked reasonWhy it can't be switched off

E_TRADE_ID_MISSINGEvery document and every output file is keyed by trade id

Can be switched off: event type, NEW/AMEND mismatch, trade date, settlement before trade, side. A test runs both engines with each of these off, to make sure they still agree.

What to remember

  • A problem is a value a mapping can't use. Each one belongs to a kind of mapping from step 3.
  • Every problem has one of five outcomes: Fixed Filled Flagged Dropped Rejected.
  • Reasons that a later mapping depends on can't be switched off.
