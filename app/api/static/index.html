Overview

One trade pipeline, built twice: once in DuckDB and once in jq. This is how they compare on your data.

1Create a dataset

Synthetic trades with deliberate mess, or your own CSV and Parquet files.

2Run the pipeline

Run DuckDB, jq or both. With both, the outputs are checked to be identical.

3Benchmark sizes

Several sizes one after another, to see how each engine scales.

    Datasets

    Five linked tables: trades, counterparties, instruments, books and FX rates. If an upload's columns don't match, fix them and save a new version.

    Runs

    Each run takes one dataset through the five stages, with one engine or both. Click a run for stage times, data quality and output files.

    Benchmarks

    Several sizes, run one after another so the timings don't compete for the CPU. Click a benchmark for its chart and numbers.

    Data

    Raw input tables, and what the pipeline made of them. Click a raw value to change it, or mark a row to remove it. Saving creates a new version and keeps the original.

    Rules

    Correction rules change values while the data is read, in both engines. Validation switches decide which problems reject a trade. Saving creates a new version: runs started afterwards use it, and every run keeps the version it used.
